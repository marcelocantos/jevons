# T1057 — controlled Pippa keyboard-boundary probe (prepared, not run)

**Permission gate:** Ask the owner to approve a short window to switch Pippa from its current activity into the already installed Flutter Jevons app and press keys on its attached hardware keyboard. No app install, uninstall, build replacement, persistent URL/settings edit, daemon restart, or message send is part of this probe. If the owner declines or the device/keyboard is unavailable, stop; hermetic tests are not a substitute for the required live caret result.

## Known facts and limit

Pippa is iPad Air 5 (`00008103-000D39301A6A201E`). Its Flutter `com.canticode.jevonsMobile` WebKit/Metal container files were modified 2026-10-10 19:42–19:44; native Swift `com.marcelocantos.jevon` last saved app state is dated April. The old native app is out of scope for this keyboard diagnosis; its retirement has a separate plan in `docs/t1057-native-duplicate-retirement-plan.md` and **nothing is uninstalled**. React `UserRequest.tsx` intercepts Alt+Up/Down and Enter, not plain arrows. Flutter 3.47.6 `WidgetsApp.defaultShortcuts` maps unmodified arrows on iOS to `DirectionalFocusIntent`; that is a source-level *suspect*, not proof Pippa's actual key event went through Flutter. The speculative Flutter remapping commit `92322920` was reverted by `3f0b2069`; no native shortcut change is pending. The Return fix in `fe118c02` stays.

## Minimal read-only sequence after permission

1. Agree the window and ask the owner to unlock Pippa and bring **Flutter Jevons** to foreground (app ID verified before testing). Do not terminate their current app remotely. Record installed bundle and version with `xcrun devicectl device info apps --device 00008103-000D39301A6A201E`; verify foreground by owner confirmation/screenshot, not merely an installed-app listing. Note the cockpit URL/build shown by the app without changing it. A page may be older than the worktree commit; record that limitation.
2. In the main composer, use an innocuous **unsent** draft of two lines (e.g. `alpha\nbravo`). Put the caret at a specified offset in the second line and note selectionStart/selectionEnd. Press plain Left, Right, Up, Down one at a time; record whether the caret moves and remains in that field. Repeat Shift+Left/Right (selection extends), Cmd+Left/Right (native line/word movement), Alt+Up/Down (existing recall, **only after ensuring no sensitive draft would be overwritten**), and unmodified Return (newline, no send). Do not press Cmd+Enter, Alt+Enter, or the Send button. If Alt recall has history content, do not copy it into the report. If that is too risky, omit Alt recall and mark it untested.
3. If Safari Develop → Pippa → Flutter WebView already exposes an inspectable page, paste `scripts/probes/t1057-key-boundary.js` into its console. The probe installs passive keydown/beforeinput/input listeners only for the focused `textarea[data-composer]`. It logs key/code, modifiers, trust, preventDefault, composer density and numeric selection offsets; **never draft text**. Maximum 40 in-memory rows, no network. For each key compare the browser's `keydown` record and before/after caret offsets. Stop with `window.__jevonsT1057Probe.stop()` and clear the unsent test draft in the app. Console contents should be reviewed/redacted before sharing a screenshot; other page logs may contain private data. The snippet's `setTimeout(0)` reports a post-dispatch sample, not a guaranteed frame-end cursor position.
4. Interpret narrowly: plain arrow missing from DOM while modified keys appear → loss before DOM (Flutter/framework/platform/WebKit ingress still needs isolation). Plain arrow present and `prevented=true` → find the specific page listener that claimed it. Present, not prevented, caret unchanged → WebKit/native default-editing boundary; compare a plain Safari textarea on the **same device/keyboard** if owner approves. Present and caret moves → intermittent or build/context-specific bug; do not call it fixed based on a one-off. Return should produce `beforeinput` `insertLineBreak`/`insertParagraph` and no send; inspect only the event type, never text. A browser DOM probe cannot establish whether Flutter saw a key when DOM never did.
5. If Web Inspector is unavailable, do **not** change release app settings, turn on remote debugging, install a modified build, or silently add logging to production. Record `inspector unavailable`, collect the manual caret matrix only, and propose a separate owner-approved diagnostic build or iOS platform event trace on an isolated test device. Stop at that boundary.

## Risks, rollback, and pass bar

Opening Pippa's app briefly interrupts whatever the owner was doing and may expose notifications/transcript content in a screen recording; avoid recording whole-screen video. Alt recall can change the draft; use a disposable draft and restore/cancel deliberately. A debug inspector can access page data even though this snippet does not: keep it local, close the inspector afterwards, do not evaluate arbitrary code. The probe itself is removed with `stop()` or page reload and makes no persistent app changes. Do not use the physical test to justify uninstalling either bundle.

Success for T1057 requires owner-observed plain-arrow caret navigation and unmodified hardware Return producing a newline without submission on the hardware-keyboard-attached Pippa. Hermetic key-policy/widget gates and the source-level Flutter shortcut finding are **not** that physical oracle. Record the exact app bundle, loaded web build, key matrix and any observed DOM boundary with the result; no target achievement on a missing/inconclusive physical result.
