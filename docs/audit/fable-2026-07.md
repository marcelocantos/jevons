## Architecture

`jevons` is a "remote control for Claude Code instances" with two components:

- **C++ app** (`bin/jevons`, `src/main.cpp`, `App.cpp`): phone UI rendered over
  the `ge` engine's WebGPU wire protocol (server on desktop, player on phone).
  Largely independent of the daemon today; not the security-load-bearing half.
- **Go coordinator** (`bin/jevonsd`, ~11k LoC, entry `cmd/jevonsd/main.go`) is
  the bulk and the security surface.

**Boot:** creates `~/.jevons/jevons` workdir, writes the overseer's `CLAUDE.md` +
`.mcp.json` (points overseer at `http://localhost:PORT/mcp`), inits an Ed25519
CA (`internal/auth`), builds manager, server, mcpserver, `claudia.Registry`
(`agents.json`), `thread.Store` (`threads.json`), butler, and the cost guard.

**HTTP:** a single `http.Server` on `:PORT` (all interfaces). Routes: DevServer
static files; `server.RegisterRoutes` → `GET /health`, `POST /api/provision`,
`/ws/chat`, `/ws/remote`, `/ws/voice`, `/ws/agent-terminal`, `GET /api/agents`,
`GET /api/cost`, `POST /api/log`, `GET|POST /api/sessions*`,
`POST /api/realtime/token`; mcpserver → `/mcp` (stateless streamable HTTP).

**Overseer:** a persistent Claude Code process named "jevons", launched via
`claudia.Registry` with `bypassPermissions` and
`DisallowTools=[Bash,Read,Write,Edit,Glob,Grep,NotebookEdit]` (main.go:418).
`/ws/chat` bridges browser text ↔ overseer PTY, streaming raw JSONL back. The
overseer delegates work only through the in-process MCP tools.

**MCP tools** (`internal/mcpserver`): `jevons_list/create/send/kill_session`,
`screenshot`, `transcript_read/rewind`, plus jwork/threads/agents tooling. These
spawn/command/kill claudia workers (Claude Code processes run with
`dangerously-skip-permissions`) hosted in a launchd-parented tmux fleet server.

**Cost clamp-down** (T36; `cmd/jevonsd/cost.go` + `internal/cost`): a collector
tails `~/.claude/projects/*.jsonl` into `~/.jevons/usage.db` (SQLite); a monitor
computes per-worker/fleet/global burn-rates and runaway signals; an enforcer
escalates warn→throttle→pause→kill with a kill-confirmation streak, dead-man's
switch, and spawn/resume guards fed into the butler; `TmuxKillSwitch` kills the
whole fleet tmux server and SIGKILLs survivors.

**Remote access:** `internal/server/relay.go` registers with a pigeon relay
(`tern.fly.dev`) so the daemon is reachable from the internet; a paired
credential derives an encrypted channel. mTLS is optional via `--tls` (off by
default); `ClientCertMiddleware` enforces client certs on all routes except
`/health` and `/api/provision`.

**Data flow:** browser/mobile → (direct WS on LAN, or pigeon relay over
internet) → jevonsd server → overseer PTY and/or MCP tools → claudia workers in
tmux fleet → Claude Code transcripts on disk → cost collector → SQLite →
monitor/enforcer → back into fleet lifecycle (pause/kill/spawn-halt) and into
the chat broadcast as `cost_alert`.

## Invariants

The audit tracked 14 invariants. Those materially implicated by confirmed
findings:

- **Inv #1** — the overseer must never hold local execution tools
  (`DisallowTools` list, main.go:418); otherwise the internet-reachable chat
  gains direct shell/file authority.
- **Inv #6/#7/#8** — the cost enforcer's global-rate kill, dead-man's switch,
  and spawn-halt are the safety net for unregistered/unattended runaway spend.
  Their inputs must not be forgeable, and `spawnHalted` must block *every*
  spawn/resume path.
- **Inv #8 (spawn-halt)** — `spawnHalted` engages on a global-kill breach or the
  hard daily ceiling and must block `AllowSpawn`/`AllowResume`. This is the cheap
  reversible guard that stops NEW spend.

Full invariant set retained from recon (Inv #2–#5, #9–#14 not contradicted by
confirmed findings this pass).

## Trust boundaries

1. **HTTP/WS listener binds `:PORT` on all interfaces; by default (no `--tls`)
   authenticates nothing.** Any host that can reach the port drives the overseer
   and MCP tools. Dominant boundary.
2. **pigeon relay** deliberately exposes the daemon to the public internet;
   gated only by the bearer relay-token plus optional pairing credential; TLS to
   the relay uses `InsecureSkipVerify:true`.
3. **`POST /api/provision`** is intentionally unauthenticated and issues a
   CA-signed client cert to any caller supplying a `device_id` + 32-byte Ed25519
   key — no pairing secret gates issuance.
4. **All WS upgrades use `websocket.Accept` with `InsecureSkipVerify:true`**,
   disabling Origin checking — a CSWSH surface.
5. **`/mcp` is stateless HTTP with no auth of its own**; any reachable caller can
   spawn/command/kill workers.
6. **Overseer runs `bypassPermissions`, workers `dangerously-skip-permissions`**:
   every tool call crosses from model-decided text into unconfirmed shell/file
   authority on the host.
7. **External API keys** load from Keychain/env; `POST /api/realtime/token`
   proxies an OpenAI ephemeral-token mint using the server's key and is
   unauthenticated (TLS off) — drivable to spend against the operator's account.
8. **The cost collector and transcript reader parse untrusted-shaped JSONL** from
   `~/.claude/projects/*.jsonl` (written by workers). Parse robustness gates
   whether a worker can spoof or suppress its own attributed spend.
9. `screenshot_result` frames carry attacker-supplied base64 written to a fixed
   `os.TempDir()/jevons-screenshot.png` at 0644.
10. Client-supplied session IDs flow into `manager.Kill` with no ownership check.
11. `POST /api/log` accepts client-posted log content without auth
    (log-injection/noise surface).

## Findings

All five confirmed findings are HIGH severity and passed both verification
lenses (reachability + invariant-validity). None was refuted by either lens.

### F1 — Unvalidated `costUSD`/token values silently suppress fleet spend accounting

- **Severity:** HIGH
- **Verdict:** CONFIRMED (reachability: confirmed; invariant-validity: confirmed)
- **Location:** `internal/cost/parse.go:60`
- **Invariant violated:** trust-boundary #8 (untrusted JSONL → SQLite → kill
  decisions; parse robustness gates spend suppression); undermines invariants
  #6, #7, #8.
- **Failure scenario:** The collector tails EVERY `*.jsonl` under
  `~/.claude/projects` (collector.go:87), and any worker runs Claude Code with
  `dangerously-skip-permissions` + a Bash tool, so it can fabricate transcript
  lines. `ParseLine` trusts `costUSD` verbatim —
  `if l.CostUSD != nil { e.CostUSD = *l.CostUSD }` — with no non-negative or
  sanity bound (Usage fields are signed `int64` accepted without a floor). A
  rogue/prompt-injected worker writes one line:
  `{"type":"assistant","sessionId":"attacker","requestId":"x1","costUSD":-100000,"message":{"usage":{"output_tokens":1}}}`.
  `InsertEvents` stores it unfiltered; `SpentUSD` sums `SUM(cost_usd)` across ALL
  sessions and `Burning` yields a large-negative unattributed row that
  `monitor.Snapshot` folds into `GlobalUSDPerHour` (monitor.go:141) and
  `SpentTodayUSD` (monitor.go:163). These feed `AlertGlobalRate`
  (attended/unattended global kill, enforcer.go:290-298), `AlertHardCeiling` /
  spawn-halt (monitor.go:218, enforcer.go:304), and the dead-man's switch. Real
  runaway burn is masked below every threshold, so no throttle/pause/kill fires —
  reproducing the invisible-runaway failure the entire subsystem exists to
  prevent. The negative row is unattributed (`Worker==""`), deflating exactly the
  global scope that is the sole backstop for the 2026-07-06 unregistered-burn
  incident class.
- **Evidence:** parse.go:60-62 (no clamp) → store.go InsertEvents `INSERT OR
  IGNORE` into `cost_usd REAL NOT NULL` (no CHECK) → store.go:134 `SELECT
  SUM(cost_usd)` and store.go:164 `SUM(cost_usd) GROUP BY session_id` →
  monitor.go:141 `globalCost += r.CostUSD`, :163 → monitor.go:188
  `LevelFor(GlobalUSDPerHour)` and :218 `SpentTodayUSD >= HardCeiling` →
  enforcer.go:290,304. Ingestion via collector.go ScanOnce WalkDir. Zero-usage
  guard (parse.go:40) is bypassed because `costUSD` is non-nil; grep across
  `internal/cost` finds no value-clamping anywhere in the parse/store/aggregate
  path.
- **Fix sketch:** In `ParseLine` clamp/reject adversarial values before building
  the Event: treat `costUSD<0` as 0 (or drop the line), and clamp each Usage
  field to ≥0 (reject the line if any is negative). Belt-and-suspenders: add a
  `CHECK(cost_usd>=0)` in `InsertEvents`, and use `GREATEST(cost_usd,0)` in the
  SUM aggregates so one poisoned row cannot cancel real spend. Prefer the
  internal pricing-table estimate over transcript-supplied `costUSD` for
  unattributed sessions.
- **Verification step:** Add a unit test that inserts a fabricated negative-cost
  line for an unattributed session and asserts `SpentUSD`/`GlobalUSDPerHour` are
  not deflated below the true attributed sum; assert the enforcer still fires
  `AlertGlobalRate`/spawn-halt on a concurrent real runaway.

### F2 — Budget spawn-halt bypassed by the primary MCP worker-spawn tools

- **Severity:** HIGH
- **Verdict:** CONFIRMED (reachability: confirmed; invariant-validity: confirmed)
- **Location:** `internal/mcpserver/jwork.go:103` (also `mcpserver.go:210` →
  `manager.go:90-98`; `agents.go:105-110`)
- **Invariant violated:** invariant #8 (`spawnHalted` must block
  `AllowSpawn`/`AllowResume`); trust-boundary #6.
- **Failure scenario:** The T36 clamp-down sets `enforcer.spawnHalted=true` on a
  global-KILL breach or hard daily ceiling (enforcer.go:304-311); `AllowSpawn`/
  `AllowResume` then refuse new spend. But those guards are wired ONLY into the
  butler (main.go:389-390 → butler.go:263/319). The three MCP tools that actually
  spawn/resume workers never consult them: jwork → `claudia.NewTask(...).Run`
  (jwork.go:103); `jevons_create_session` → `mgr.Create` →
  `claudia.NewTask(...).Run` (manager.go:90-98); `jevons_agent_start` →
  `registry.EnsureAgent`+`Launch` (agents.go:105-110, also skipping
  `AllowResume` when re-launching a pause/kill-clamped worker). Concrete: hard
  ceiling trips, `spawnHalted` engages, the enforcer stops the fleet — and the
  overseer (or any host reachable on `/mcp`, trust boundary 5/6) immediately
  calls `jwork` or `jevons_create_session` and spawns unlimited fresh workers,
  re-igniting exactly the runaway the clamp exists to stop.
- **Evidence:** enforcer.go:305-310 sets `spawnHalted`; `AllowSpawn`
  enforcer.go:120-123, `AllowResume` :134-137. Guards wired only to butler at
  main.go:389-390, consumed butler.go:263/319. Bypassing paths: jwork.go:103;
  mcpserver.go:210 → manager.go:90-98; agents.go:105-110. `mcpserver.Server`
  struct (mcpserver.go:41-57) has no guard field. HTTP exposure at
  mcpserver.go:144,150 (`StreamableHTTPServer` on `/mcp`). Repo-wide grep shows
  no guard consumer outside butler + tests.
- **Fix sketch:** Route every worker-spawn/resume path through a single guard.
  Give `mcpserver.Server` a `SpawnGuard`/`ResumeGuard` func (wired from
  `guard.enforcer.AllowSpawn`/`AllowResume` like the butler) and call it at the
  top of `handleJwork`, `handleCreateSession`, and `handleAgentStart` before
  creating/launching; return the guard error as a tool error.
- **Verification step:** Integration test: force `spawnHalted=true`, then invoke
  each of `jwork`/`jevons_create_session`/`jevons_agent_start` over `/mcp` and
  assert each returns a guard error and spawns no worker.

### F3 — Cross-Site WebSocket Hijacking on all WS endpoints

- **Severity:** HIGH
- **Verdict:** CONFIRMED (reachability: confirmed; invariant-validity: confirmed)
- **Location:** `internal/server/server.go:354-356` (handleRemote); also
  `chat.go:194-196`, `terminal.go:41-42`, `voice.go:138-139`
- **Invariant violated:** trust-boundary #4 (also #1).
- **Failure scenario:** Every `websocket.Accept` passes
  `InsecureSkipVerify:true`, disabling coder/websocket's same-origin check. The
  listener binds `:PORT` on all interfaces and, with `--tls` off (default),
  authenticates nothing. While the operator has the cockpit open and browses to
  an attacker page, that page runs
  `new WebSocket("ws://localhost:13705/ws/remote")` (or `/ws/chat`,
  `/ws/agent-terminal`); the handshake succeeds cross-origin, and the page sends
  `{"type":"message","text":...}` / `{"action":"kill_session:<id>"}` frames that
  drive the overseer PTY and spawn/command/kill workers running with
  `dangerously-skip-permissions`. `/ws/agent-terminal` bridges a worker PTY,
  giving the remote page an interactive shell on the host.
- **Evidence:** `InsecureSkipVerify:true` at server.go:354-355, chat.go:194-195,
  terminal.go:41-42, voice.go:138-139 (also server.go:199). Bind: main.go:424
  `:%d` default port 13705 (main.go:172). Auth: `--tls` default false
  (main.go:179); `ClientCertMiddleware` applied only `if *enableTLS`
  (main.go:428); handler is bare `mux` otherwise (main.go:427). Frame dispatch:
  server.go:388-428 read loop → `HandleUserMessage`/`HandleControl`/
  `HandleAction`. No Origin/CORS middleware exists in `internal/server`.
- **Fix sketch:** Replace `InsecureSkipVerify:true` with an explicit
  `OriginPatterns` allowlist (localhost + paired device origins) on every
  `websocket.Accept`, or validate the Origin header against a configured
  allowlist before upgrading. Reject upgrades whose Origin is absent or unlisted.
- **Verification step:** Add a test that performs a WS handshake with a foreign
  `Origin` header and asserts the upgrade is rejected; a matching-origin
  handshake still succeeds.

### F4 — Unauthenticated, CSRF-able state-changing and money-spending HTTP endpoints

- **Severity:** HIGH
- **Verdict:** CONFIRMED (reachability: confirmed; invariant-validity: confirmed)
- **Location:** `internal/server/server.go:177-187` (routes),
  `server.go:218-246` (handleRealtimeToken), `server.go:481-491`
  (handleKillSession)
- **Invariant violated:** trust-boundary #7, #10.
- **Failure scenario:** `POST /api/realtime/token`, `/api/sessions/{id}/kill`,
  `/api/provision`, `/api/log` have no Origin check, no CSRF token, and (default,
  TLS off) no client-cert requirement. `handleRealtimeToken` reads no request
  body, so a cross-origin
  `fetch('http://localhost:13705/api/realtime/token',{method:'POST'})` (a
  CORS-simple request needing no preflight) from any page the operator visits
  makes the daemon mint OpenAI ephemeral sessions against the operator's
  key/billing; `handleKillSession` lets the same page terminate any tracked
  worker by id (`manager.Kill` has no ownership check); `handleProvision` lets it
  mint a CA-signed client cert (JSON sendable as `text/plain` to dodge preflight,
  since no Content-Type check). CORS blocks reading the response, not causing the
  side effect. Additionally the all-interfaces bind makes a direct
  `curl -X POST http://<lan-ip>:13705/api/sessions/<id>/kill` succeed with zero
  auth — no browser required.
- **Evidence:** main.go:179 (`tls` default false), :427-430 (middleware only
  wraps when `enableTLS`), :424 (`:%d` all-interfaces bind). server.go:175-189
  (routes, no auth), :218-246 (handleRealtimeToken proxies with `s.openAIKey`,
  reads no body), :279-323 (handleProvision, no Content-Type check; CA set
  unconditionally at main.go:263), :481-491 (handleKillSession).
  manager.go:264-277 (Kill, no ownership check). No Origin/CSRF check in any
  handler.
- **Fix sketch:** Gate state-changing/spending routes behind the same auth as
  everything else (require the paired credential / client cert even in non-TLS
  mode), and add an Origin/`Sec-Fetch-Site` check rejecting cross-site POSTs. Add
  per-owner rate limiting on the token-mint proxy. Bind loopback-only unless the
  relay/pairing path is active.
- **Verification step:** Test that an unauthenticated cross-site POST to each
  endpoint is rejected (401/403); a properly authenticated same-origin request
  still succeeds. Confirm no OpenAI session is minted for the rejected request.

### F5 — `sendHistory` silently truncates overseer history at the first >1 MB JSONL line

- **Severity:** HIGH
- **Verdict:** CONFIRMED (reachability: confirmed; invariant-validity: confirmed)
- **Location:** `internal/server/chat.go:311-329` (cap set at :319;
  `scanner.Err()` never checked)
- **Invariant violated:** none (adjacent to trust-boundary #8 transcript-parsing
  robustness); a correctness/robustness defect against `sendHistory`'s own "send
  each line" contract.
- **Failure scenario:** A `/ws/chat` client connects; the server replays the
  overseer transcript via `sendHistory`, which uses a `bufio.Scanner` capped at
  `1<<20` bytes (`scanner.Buffer(make([]byte,1<<20),1<<20)`). The overseer's own
  transcript legitimately contains `tool_result` lines that run to megabytes
  (e.g. a `jevons_transcript_read` of a large worker session) — exactly the case
  `tail.go:45-46` documents. When `Scan()` hits such a line it returns false with
  `bufio.ErrTooLong`; the for-loop exits, `scanner.Err()` is discarded, and every
  subsequent history line is silently dropped. The client sees a truncated
  conversation with no error, and because truncation is deterministic,
  reconnecting reproduces the broken view.
- **Evidence:** chat.go:318-328 (Scanner cap `1<<20`, no `scanner.Err()` check,
  silent loop exit on `bufio.ErrTooLong`); called from chat.go:208-217 on
  `/ws/chat` connect with `proc.JSONLPath()` (overseer transcript). Contrast
  `internal/cost/tail.go:45-51` (`Reader.ReadBytes` to handle megabyte
  tool-result lines) and `transcript.go:141,313` (paths that DO propagate
  `scanner.Err()`). The inbound `conn.SetReadLimit(1<<20)` at chat.go:203 does
  not bound outbound line size.
- **Fix sketch:** Read history with `bufio.Reader.ReadBytes('\n')` (the pattern
  `tail.go` already uses) instead of a size-capped Scanner, or raise/remove the
  cap AND check `scanner.Err()` at the end, surfacing a websocket error frame
  when history could not be fully replayed.
- **Verification step:** Write a transcript fixture containing a >1 MB line
  followed by additional lines; assert `sendHistory` replays all lines (or emits
  an explicit error frame), not a silent prefix.
