# Backend unification audit

The shared participant model has substantially landed. The React conversation path addresses Jevons, a PO, a worker, or an aside by name and uses the same widget, mux channel, paging protocol, event store, and core fleet delivery function. The remaining problems are concentrated at adapters and lifecycle boundaries. A wholesale backend rewrite would discard working machinery. However, the stronger claim that the same conversation semantics apply to every participant is not yet true: fresh isolated probes reproduced two consequential divergences.

This review covers committed `8dd6e1694bbf` in the frozen checkout. Current uncommitted T621/T622 changes are described separately and were **not** included in the executed gates. No provider turn, development daemon, or product state was touched. The user's latest instruction supersedes the old sidebar's behavior: the reference is the main conversation model shared across participants, not preservation of old sidebar quirks.

## Consequential gaps

**B1 — Agent-origin user turns can be missing from the React transcript. Reproduced, high priority.** The worker event path records a `user` event to JSONL and returns before mux/SQLite ingestion; its subsequent assistant event does reach mux. HTTP owner sends take a separate pre-journal path and reach mux themselves. Once an agent already has SQLite history, the mux never reimports the new JSONL-only user turn. The resulting conversation can show a reply without the agent message that prompted it. The probe initialized a worker conversation, injected a provider user event and reply through `DeliverInspectLive`, and refreshed the mux: the user existed in JSONL but not SQLite/mux; the reply and a later HTTP-owner pre-journal control were present. [agent_chatlog.go:340](/private/tmp/jevons-audit-20260905/checkout/internal/server/agent_chatlog.go:340), [agent_chatlog.go:361](/private/tmp/jevons-audit-20260905/checkout/internal/server/agent_chatlog.go:361), [convomux.go:828](/private/tmp/jevons-audit-20260905/checkout/internal/server/convomux.go:828). Fix the one ingestion path and test provider-user events with a populated database, not only a fresh journal.

**B2 — Delivery acknowledgement changes with the API door. Reproduced, high priority.** `sendToNamedAgentAs` branches on overseer before the common fleet hook and reports `sent` after `SendToOverseer`, whose return only means accepted into its queue. The probe held the overseer sender busy: HTTP returned `sent` while the owner payload remained queued; the worker control returned `queued`. Calling the common MCP entry without receiver evidence instead correctly returned `delivered_unconfirmed`. [agent_send.go:70](/private/tmp/jevons-audit-20260905/checkout/internal/server/agent_send.go:70), [chat.go:458](/private/tmp/jevons-audit-20260905/checkout/internal/server/chat.go:458), [deliver_by_name.go:492](/private/tmp/jevons-audit-20260905/checkout/internal/mcpserver/deliver_by_name.go:492). The mux discards even the status, sends only an uncorrelated error, and the UI clears a draft on its transcript echo, which is emitted before delivery. [convomux.go:725](/private/tmp/jevons-audit-20260905/checkout/internal/server/convomux.go:725), [useConversation.ts:16](/private/tmp/jevons-audit-20260905/checkout/ui/src/conversation/useConversation.ts:16), [agent_conversation.go:208](/private/tmp/jevons-audit-20260905/checkout/internal/server/agent_conversation.go:208). Preserve an echo as evidence of recording, but make acceptance, queued, provider-confirmed, and terminal failure explicit and correlated across every transport.

**B3 — The outstanding-delivery contract is not shared or crash-safe. Source-confirmed, already captured by T623.** Worker send queues are durable while held, but `PopFront` persists removal before delivery; definite non-delivery during drain logs and returns without restoring the entry. The overseer's notify queue is an in-memory slice. Owner transcript durability, stored worker reports, replay suppression and recovery heuristics mitigate loss but do not constitute a durable ledger of all pending delivery obligations. [sendq.go:275](/private/tmp/jevons-audit-20260905/checkout/internal/sendq/sendq.go:275), [agent_send.go:628](/private/tmp/jevons-audit-20260905/checkout/internal/mcpserver/agent_send.go:628), [agent_send.go:668](/private/tmp/jevons-audit-20260905/checkout/internal/mcpserver/agent_send.go:668), [server.go:194](/private/tmp/jevons-audit-20260905/checkout/internal/server/server.go:194). Implement the T623 contract once, retaining entries until receiver evidence or a durable terminal outcome; do not blindly resend ambiguous submissions.

**B4 — Speaker origin is not preserved uniformly. Source-confirmed.** The HTTP hook accepts only `(name,text)` and main wires the owner-default `DeliverAgentMessage`, although the HTTP request accepts `origin`. The worker provider-user event fallback also uses `appendUser`, which defaults to owner origin; MCP sends do not call the server's pre-journal method. Owner/agent distinctions in worker history therefore depend on which entry point and provider echo were used. [main.go:980](/private/tmp/jevons-audit-20260905/checkout/cmd/jevonsd/main.go:980), [agent_send.go:103](/private/tmp/jevons-audit-20260905/checkout/internal/server/agent_send.go:103), [agent_chatlog.go:149](/private/tmp/jevons-audit-20260905/checkout/internal/server/agent_chatlog.go:149). Carry authenticated speaker/provenance with the message through common admission and journaling; do not reconstruct origin from provider text. This complements B1 rather than requiring a second transcript implementation.

**B5 — Lifecycle recovery has duplicated policy that already differs. Source-confirmed.** `GET /api/agents` does its own dead-handle recovery and relaunches dead `AutoStart` seats without consulting fleet intent. `SweepDeadAgents` explicitly asks persisted intent before revive, and ordinary fleet send's rehydrate arm also checks intent. This is more than a role difference: opening/polling the fleet list reaches another recovery policy. [chat.go:900](/private/tmp/jevons-audit-20260905/checkout/internal/server/chat.go:900), [fleet_health.go:153](/private/tmp/jevons-audit-20260905/checkout/internal/mcpserver/fleet_health.go:153), [agent_send.go:178](/private/tmp/jevons-audit-20260905/checkout/internal/mcpserver/agent_send.go:178). Consolidate the decision in a package both server layers can use. No production resurrection was observed in this audit; the causal claim is limited to a dead handle plus `AutoStart` plus contrary intent.

**B6 — The mux send arm still uses the wrong lock for subscription state. Source-confirmed concurrency risk.** `muxWatch.window/subscribeTo` protect `visible/sub` with the watch's mutex, but `handleMuxEnvelope(send)` mutates them under the session mutex. A send can race a simultaneous fan or window operation. The existing T590 concurrency test covers accessor calls and the sent-ID map, not this send handler. [convomux.go:57](/private/tmp/jevons-audit-20260905/checkout/internal/server/convomux.go:57), [convomux.go:716](/private/tmp/jevons-audit-20260905/checkout/internal/server/convomux.go:716), [convomux_race_test.go:19](/private/tmp/jevons-audit-20260905/checkout/internal/server/convomux_race_test.go:19). Use the watch-owned operation and add a race test that invokes the actual send handler. No race-detector run was performed for this finding.

## Role policy versus plumbing

The overseer should remain the owner's reporting sink; owner turns outranking/coalescing background reports, persistent PO seats, disposable completed workers, lineage authorization, and provider capability differences are legitimate policy. Those do not require a separate transcript, delivery receipt, journal, or retry contract.

Some implementation asymmetry is presently necessary but should stay behind a participant adapter. The overseer process has an extra `AttachOverseer` subscription and recovery loop; migration must reattach it. The old migration API prevents MCP callers from migrating an overseer and directs them to an overseer-only HTTP endpoint, partly because it assumes the overseer is the session answering the tool. Fleet migration and overseer migration share rotation and pending handover storage, but the overseer seed marks delivered on `sendNotes` returning nil, whereas fleet seed delivery consults receiver evidence. [migrate_overseer.go:124](/private/tmp/jevons-audit-20260905/checkout/internal/server/migrate_overseer.go:124), [migrate_overseer.go:185](/private/tmp/jevons-audit-20260905/checkout/internal/server/migrate_overseer.go:185), [migrate.go:83](/private/tmp/jevons-audit-20260905/checkout/internal/mcpserver/migrate.go:83), [fleet/migrate.go:405](/private/tmp/jevons-audit-20260905/checkout/internal/fleet/migrate.go:405). The role may alter permission and scheduling; receiver-confirmation semantics should not depend on role.

`thread_direct` remains a synchronous request/reply operation with takeover checks for observe-only adopted threads. T309.3 explicitly accepted that distinct operation. It is not, by itself, evidence that shared conversation failed. Its implementation still goes through Butler/Fleet delivery rather than the durable send queue, so callers must understand its different completion contract. [butler.go:345](/private/tmp/jevons-audit-20260905/checkout/internal/butler/butler.go:345), [fleet.go:556](/private/tmp/jevons-audit-20260905/checkout/internal/fleet/fleet.go:556).

Two smaller residues: `muxTranscriptMeta` includes overseer working/phase/down state on every named channel rather than querying the named participant; current compact widgets do not paint the overseer strip, masking most of that mismatch. Also role policy still includes name conventions such as `isPOName`, so shared registry shape does not mean every role decision is fully data-driven. Neither warrants a new orchestrator architecture.
